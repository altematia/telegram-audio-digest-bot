# Telegram Audio Digest Bot

Минималистичный Telegram-бот: принимает голосовые сообщения и аудио/MP3/MP4-файлы, расшифровывает их через OpenAI и сразу показывает краткую нейровыжимку. Под каждым результатом остаются кнопки:

- кратко;
- подробно;
- ключевые тезисы;
- задачи и решения;
- полная расшифровка.

## Как это устроено

- `aiogram` и long polling — без отдельного веб-сервера;
- OpenAI `gpt-transcribe` — транскрибация;
- OpenAI Responses API и `gpt-5.6-terra` — выжимки;
- SQLite — хранение расшифровок и кэш готовых форматов в течение 30 дней;
- systemd — один постоянно работающий процесс на сервере;
- FFmpeg — только для автоматического преобразования Telegram OGG/Opus в поддерживаемый OpenAI WebM. MP3/MP4 отправляются в OpenAI напрямую.

Аудиофайлы сохраняются только во временную директорию и удаляются сразу после обработки. Telegram Bot API позволяет скачать файл размером до 20 МБ; это ограничение выставлено по умолчанию.

Доступ закрыт по умолчанию. Владельцев можно явно перечислить в `ALLOWED_USER_IDS`; если ID заранее неизвестен, задаётся длинный одноразовый `BOT_CLAIM_SECRET`, после чего владелец один раз отправляет боту `/claim <секрет>`. Простое первое сообщение никогда не захватывает бота. Одновременно обрабатывается не больше четырёх обновлений, чтобы случайный всплеск не создал неограниченные расходы API.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
.venv/bin/python -m app.main
```

В `.env` нужны `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`. Сам `.env` исключён из Git.

## Тесты

```bash
.venv/bin/python -m pytest
```

Безопасный smoke-тест реальных Telegram/OpenAI API (ключи не выводятся):

```bash
.venv/bin/python scripts/smoke-test.py
```

## Сервер

Продакшен расположен в `/opt/telegram-audio-digest-bot`, секреты — в `/etc/telegram-audio-digest-bot.env`, данные — в `/var/lib/telegram-audio-digest-bot`.

На текущем сервере прямой маршрут к Telegram API заблокирован провайдером, а прямой OpenAI API недоступен из региона. Поэтому оба API-трафика приложения направлены через локальный SOCKS5 `127.0.0.1:9050` (Tor + официальный Snowflake/Lyrebird); SSH и остальной трафик сервера не меняются. Это задаётся через `TELEGRAM_PROXY_URL` и `OPENAI_PROXY_URL`; systemd запускает бот после Tor.

Первичная установка от `root`:

```bash
bash scripts/install-server.sh
```

Каждое обновление после `git push`:

```bash
bash scripts/deploy.sh
```

Скрипт подключается к серверу, выполняет `git pull --ff-only`, обновляет зависимости, перезапускает systemd-сервис и проверяет его статус.
